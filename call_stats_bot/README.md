# Мини-бот статистики звонков МегаФон ВАТС

Сервис принимает от ВАТС финальное событие `history`, сохраняет звонок в
SQLite и ежедневно отправляет в Telegram количество и суммарную длительность
по выбранным сотрудникам. Команда `/today` присылает текущую статистику сразу.

В момент ежедневного отчёта сервис также ставит доступные записи звонков в
обработку: скачивает аудио во временный защищённый файл, транскрибирует с
разделением спикеров, определяет менеджера и клиента, формирует краткую выжимку
и сохраняет результат в SQLite. Аудиофайл после обработки удаляется.

## Запуск

```bash
cp call_stats_bot/.env.example .env.calls
# заполнить .env.calls
python -m uvicorn call_stats_bot.main:app --host 0.0.0.0 --port 8001
```

В личном кабинете ВАТС откройте **Настройки → Интеграция с CRM → Ваша CRM /
REST API** и задайте:

- URL CRM: `https://ваш-домен/megafon/webhook`;
- токен CRM: значение `CALLBOT_MEGAFON_CRM_TOKEN`.

ВАТС должна присылать команду `history` после завершения звонка. Идентификаторы
из поля `ext` перечисляются в `CALLBOT_EMPLOYEES`; остальные сотрудники
игнорируются.

Если заданы `CALLBOT_MEGAFON_API_URL` и `CALLBOT_MEGAFON_API_KEY`, перед каждым
отчётом сервис читает актуальные имена сотрудников из `GET /users`. При
временной недоступности API используются имена из `CALLBOT_EMPLOYEES`.

Зарегистрируйте Telegram webhook:

```bash
curl -X POST "https://api.telegram.org/bot<TOKEN>/setWebhook" \
  -d "url=https://ваш-домен/telegram/webhook" \
  -d "secret_token=<CALLBOT_TELEGRAM_WEBHOOK_SECRET>"
```

Проверка: отправьте боту `/start` или `/today`. Автоматический отчёт уходит в
`CALLBOT_REPORT_TIME` по часовому поясу `CALLBOT_TIMEZONE`.

## Отчёты и расшифровки в Telegram Mini App

Укажите публичный HTTPS-адрес страницы `/support/` в
`CALLBOT_MINIAPP_PUBLIC_URL`. В ежедневном сообщении и команде `/start`
появится кнопка «Отчёты и звонки». Доступ к API Mini App проверяется по
подписи Telegram и разрешён только пользователям из
`CALLBOT_TELEGRAM_ADMIN_IDS`.

Интерфейс построен на карточках: день → менеджер → звонки. В карточке звонка
показывается краткая выжимка, важные факты и следующие шаги; полная
транскрипция со спикерами раскрывается по запросу. Команда `/analyze_today`
повторно запускает незавершённую обработку текущего дня. Успешно обработанные
звонки повторно не тарифицируются.

Для обработки задайте `CALLBOT_OPENAI_API_KEY`. Число параллельных звонков
ограничивается `CALLBOT_ANALYSIS_CONCURRENCY` (рекомендуется 2). Результат
каждого звонка фиксируется сразу, поэтому рестарт не теряет прогресс.

## Временное замещение в Bitrix24

Сервис умеет временно переводить активные сделки одного ответственного на
другого и автоматически возвращать их. До изменения каждой сделки исходный
ответственный записывается в локальный журнал. После записи и после возврата
сделка повторно читается из Bitrix24. Новые активные сделки отсутствующего
сотрудника подхватываются фоновым циклом.

Предпочтительный способ подключения — внутренний Bitrix Gateway через
`CALLBOT_BITRIX_GATEWAY_*`. Прямой вебхук также поддерживается переменной
`CALLBOT_BITRIX_WEBHOOK_URL`, но секрет нельзя хранить в репозитории или
передавать в логах.

Администраторы перечисляются в `CALLBOT_TELEGRAM_ADMIN_IDS`. Для обработки
команд можно зарегистрировать `/telegram/webhook` либо включить
`CALLBOT_TELEGRAM_POLLING_ENABLED=true`, но не оба варианта одновременно.

Команды:

- `/start` или `/replace` — открыть пошаговый мастер с кнопками: исходный
  менеджер → срок возврата → замещающий менеджер → подтверждение;
- `/replace 713 708 2026-10-15 20:00` — подготовить перенос между сотрудниками
  телефонии и показать количество;
- `/confirm 1a2b3c4d` — подтвердить подготовленную операцию;
- `/cancel 1a2b3c4d` — отменить неподтверждённый черновик;
- `/restore 1a2b3c4d` — начать возврат досрочно;
- `/bitrix_users` — показать разрешённые внутренние номера, имена и Bitrix ID;
- `/replacements` — показать последние операции.

В мастере доступны готовые сроки (сегодня вечером, завтра утром/вечером,
через неделю) и ручной ввод в формате `ДД.ММ.ГГГГ ЧЧ:ММ`. Состояние мастера
хранится в SQLite и не теряется при перезапуске контейнера.

После подтверждения сообщение превращается в обновляемый прогресс-бар. Сделки
обрабатываются безопасными пачками по 20 и не более чем по 5 параллельно;
исходный ответственный по-прежнему фиксируется до каждого изменения, а запись
в Bitrix24 перечитывается после него.

Время трактуется в `CALLBOT_TIMEZONE`. Если во время замещения сделку вручную
передали третьему сотруднику, сервис не перезаписывает это решение: операция
переходит в состояние `attention`, а сделка остаётся в журнале как конфликт.
Источником и получателем могут быть только сотрудники, одновременно указанные
в `CALLBOT_EMPLOYEES` и `CALLBOT_BITRIX_USER_MAP`; произвольный Bitrix ID бот не
принимает.

Состав сотрудников обновляется из Bitrix24 каждые пять минут. Активные
сотрудники показываются всегда. Уволенный сотрудник остаётся в списке источников
только пока на нём есть хотя бы одна незакрытая сделка; получателем замещения
может быть только активный сотрудник.

## Docker

Из корня репозитория:

```bash
docker build -f call_stats_bot/Dockerfile -t megafon-call-stats .
docker run --env-file .env.calls -p 8001:8000 \
  -v "$PWD/data:/app/data" megafon-call-stats
```
